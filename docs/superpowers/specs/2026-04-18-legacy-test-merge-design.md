# Design: Legacy Test Merge in migrate-visual-tests.js

**Date:** 2026-04-18
**Scope:** `scripts/migrate-visual-tests.js` + `tests/integration/test_migrate_visual.py`

---

## Problem

When `spec.migrate` runs, `migrate-visual-tests.js --generate` deletes old hand-crafted test files (e.g., `audit.spec.ts`) after generating their route-scan replacements (e.g., `route-audit.spec.ts`). The old files often contained custom, high-value test logic (specific API mocks, interaction flows, error states) that the blank template does not reproduce.

**Result:** custom test knowledge is silently lost.

---

## Solution Overview

Before generating a `route-{slug}.spec.ts`, detect if a legacy `{slug}.spec.ts` exists. If so:

1. Extract custom test blocks (those not matching the 4 standard template tests)
2. Extract additional imports used by those custom tests
3. Generate the standard template
4. Merge imports + inject custom blocks into the generated file
5. Only delete the legacy file after verifying all custom blocks are present

---

## Architecture

### New Constants

```js
// Must stay in sync with the test names generated by generateE2ETemplate()
const STANDARD_TEST_NAMES = [
  'full page with data',
  'empty state — no data',
  'page header and navigation',
  'mobile view',
];
```

### New Functions

#### `findLegacyTestFile(slug, testDir) → string|null`
Returns path to `{testDir}/{slug}.spec.ts` if it exists and is not route-prefixed or numbered.

```
slug = routeFeature.slug  (e.g. "audit" from "route-audit.spec.ts")
candidate = {testDir}/{slug}.spec.ts
if exists AND not /^\d{3}-/.test(candidate) AND not /^route-/.test(basename)
  → return path
else
  → return null
```

#### `extractCustomTestBlocks(content) → Array<{name, block}>`
Regex-based extraction of `test(...)` blocks whose name is not in `STANDARD_TEST_NAMES`.

Algorithm:
1. Match each `test('...', async ...` opening line
2. Track brace depth to find the corresponding `});` close
3. Return the full block as a string, paired with the extracted test name
4. Skip blocks whose name (lowercased) matches any `STANDARD_TEST_NAMES` entry

#### `mergeAdditionalImports(templateContent, legacyContent) → string`
Returns updated `templateContent` with additional imports from `legacyContent` injected after existing import block.

Internally calls `extractAdditionalImports(legacyContent, templateContent) → string[]` which:

Algorithm:
1. Parse all `import { ... } from '...'` lines from both files
2. For each symbol in legacy imports, check if already present in template (by symbol name)
3. If symbol absent: include the import line
4. If symbol present but different path: log `[WARN] Import conflict: <symbol>` to console (do NOT add to file)

#### `injectCustomTestBlocks(templateContent, customBlocks, sourceSlug) → string`
Injects custom blocks after `mobile view` test, before the final `});` of `test.describe`.

Algorithm:
1. Validate `mobile view` test is present in template; if not, log warning and use fallback
2. Find the closing `});` that ends the `test.describe(...)` block
3. Insert:
   ```
   \n  // ── Preserved from <sourceSlug>.spec.ts ──\n
   <block1>\n\n
   <block2>\n
   ```
4. Return modified content

#### `verifyCustomBlocksPresent(generatedContent, customBlocks) → string[]`
Returns names of custom blocks whose test name literal was not found in `generatedContent`.

Used in deletion guard: if any name missing → skip deletion.

## Modified Functions

### `generateRouteTest(routeFeature, analysis, dryRun)`

**Before writing:**
1. Call `findLegacyTestFile(slug, TEST_DIR)` → `legacyPath`
2. If `legacyPath`: read content, extract `customBlocks`, extract `additionalImports`
3. Generate `templateContent` via `generateE2ETemplate()`
4. If `customBlocks.length > 0`:
   - Call `mergeImports(templateContent, additionalImports)` → updated template
   - Call `injectCustomTestBlocks(template, customBlocks, slug)` → final content
   - Log: `  [MERGE] ${customBlocks.length} custom test(s) from ${slug}.spec.ts → ${testPath}`
5. Write final content

**Return value:** `{ customBlocks, legacyPath }` (or `null` if no merge)

### `generateTests(features, dryRun)`

**Phase 2 (route-scan):** collect merge results:
```js
const mergeResults = new Map(); // legacyPath → customBlocks[]
for (const routeFeature of routeScanFeatures) {
  const result = generateRouteTest(routeFeature, analysis, dryRun);
  if (result?.legacyPath) mergeResults.set(result.legacyPath, result.customBlocks);
}
```

**Phase 4 (delete superseded):** pass `mergeResults` to `deleteSupersededTests`.

### `deleteSupersededTests(allCoveredRoutes, dryRun, mergeResults)`

For each superseded file about to be deleted:
- If `mergeResults.has(filePath)` AND `mergeResults.get(filePath).length > 0`:
  - Read the generated route-* file
  - Call `verifyCustomBlocksPresent(generatedContent, customBlocks)`
  - If `missing.length > 0`:
    - Log `[WARN] Legacy test not found in output: "<name>" — skipping deletion of <file>`
    - Skip deletion
  - Else: proceed with deletion as normal
- If not in mergeResults (no custom blocks): delete as normal

## Edge Cases

| Case | Behavior |
|------|----------|
| Legacy file has no custom tests (all standard) | No injection, standard deletion |
| Legacy file has test name with special chars | Regex handles escaped quotes; name literal search is substring-safe |
| `mobile view` not in generated template | Warning logged, injection at end of describe |
| Same import symbol, different path | Symbol not re-added; `[WARN]` to console only |
| Legacy file is empty or unparseable | `extractCustomTestBlocks` returns `[]`, no merge |
| Route-* file doesn't exist yet (dry run) | No verification, no deletion (dry run skips both) |

---

## Non-Goals

- No spec.md changes (behavior is additive, not breaking)
- No changes to numbered test (NNN-*) handling
- No LLM-assisted merge (pure static analysis)
