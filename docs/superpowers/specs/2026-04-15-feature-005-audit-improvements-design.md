## Design Decisions

### 1.1 — Status fix
The spec.md frontmatter (line 4) already has `status: Planned`. Only the body markdown (line 17) says `**Status:** Draft`. Fix the body only.

### 3.1 — Taxonomy versioning
Add `**Taxonomy Version:** v1.0.0` immediately after the existing `**Version:** 2026-04-14` line. Add a `## Changelog` section at the bottom of the file. Add `<!-- Generated by ui-behavioral-taxonomy v1.0.0 -->` comment guidance in the `## Behavioral AC` section note (already in commands, not in the taxonomy itself — noted as a convention for generated specs).

### 2.1 — Detection examples format
For each of the 5 traits, add a `**Detection examples:**` block after the detection signals table, with:
- ✅ **INJECT** examples (2-3 per trait)
- ❌ **DO NOT INJECT** examples (2-3 per trait)
- **Ambiguous cases** where ≥2 signals are required

### 1.2 / 2.2 / 2.3 — .feature files
Standard Gherkin format. These are specification documents that guide LLM behavior when executing `/spec.implement` and `/spec.test`. They are not run by a test runner — they are read by the AI agent.

### 3.2 — Review process
Standalone markdown document co-located with the taxonomy. Covers: frequency, checklist, criteria for adding/modifying traits.

### 3.3 — Dashboard backlog
Not implemented. A note is added to the feature 005 changelog documenting the `/spec.stats --behavioral` command as a feature 006 candidate.
