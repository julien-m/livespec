FR Dependency Graph

LiveSpec Playground — Interactive dependency graph of Functional Requirements

What is this playground for?

The FR Dependency Graph generates an interactive force-directed graph from a spec.md file. It visualizes the relationships between Functional Requirements (FR), their Acceptance Criteria (AC), and their implementation status.

The main goal is to identify critical dependencies before splitting a plan into steps: which FRs are prerequisites for others, where the bottlenecks are, and what the longest dependency chain (critical path) looks like.

How to use — step by step

1
Load a .specs project Click Load Project to open a directory containing a .specs/features/ folder. Select a feature from the dropdown. The graph is generated automatically from the feature's spec.md, plan.md, and implementation.md files.
2
Explore the graph
  • Zoom — mouse wheel
  • Pan — click-drag on the background
  • Move a node — click-drag on a node
  • Hover — highlights the node and its direct neighbors, dims everything else
  • Click — selects the node and shows its details in the right panel
3
Show/hide ACs Use the Show ACs button to display Acceptance Criteria as small satellite nodes around each FR. Useful for seeing the relative complexity of each requirement.
4
Identify the Critical Path Click Critical Path to highlight the longest dependency chain in the graph. This is the sequence that determines the minimum implementation order.
5
View FR details The right panel shows for each selected FR: its ID, full description, ACs, source file with @spec anchor (if implementation.md provided), plan step, and incoming/outgoing dependencies (clickable to navigate).

Metrics (top bar)

The metrics bar shows in real-time: total FR count, implemented, in progress, blocked, and a progress bar for overall coverage.

FR Dependency Graph

LiveSpec Playground — Graphe interactif des dépendances entre Functional Requirements

A quoi sert ce playground ?

Le FR Dependency Graph génère un graphe force-directed interactif à partir d'un fichier spec.md. Il visualise les relations entre les Functional Requirements (FR), leurs Acceptance Criteria (AC), et leur statut d'implémentation.

L'objectif principal est d'identifier les dépendances critiques avant de découper un plan en steps : quelles FR sont des prérequis pour d'autres, où sont les goulots d'étranglement, et quelle est la chaîne de dépendances la plus longue (critical path).

Comment l'utiliser — étape par étape

1
Charger un projet .specs Cliquez sur Load Project pour ouvrir un dossier contenant .specs/features/. Sélectionnez une feature dans le menu déroulant. Le graphe est généré automatiquement à partir des fichiers spec.md, plan.md et implementation.md de la feature.
2
Explorer le graphe
  • Zoom — molette de souris
  • Pan — cliquer-glisser sur le fond
  • Déplacer un noeud — cliquer-glisser sur un noeud
  • Survol — met en surbrillance le noeud et ses voisins directs, atténue le reste
  • Click — sélectionne le noeud et affiche ses détails dans le panneau droit
3
Afficher/masquer les AC Utilisez le bouton Show ACs pour afficher les Acceptance Criteria comme des petits noeuds satellites autour de chaque FR. Utile pour voir la complexité relative de chaque requirement.
4
Identifier le Critical Path Cliquez sur Critical Path pour mettre en surbrillance la chaîne de dépendances la plus longue dans le graphe. C'est la séquence qui détermine l'ordre minimal d'implémentation.
5
Consulter les détails d'un FR Le panneau droit affiche pour chaque FR sélectionné : son ID, sa description complète, ses AC, le fichier source avec l'ancre @spec (si implementation.md fourni), le step du plan, et la liste des dépendances entrantes/sortantes (cliquables pour naviguer).

Métriques (barre du haut)

La barre de métriques affiche en temps réel : le nombre total de FR, le nombre implémenté, en cours, bloqué, et une barre de progression du coverage global.
