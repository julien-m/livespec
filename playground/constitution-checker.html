Constitution Rule Checker

LiveSpec Playground — Heuristic architecture rule checker

What is this playground for?

The Constitution Rule Checker analyzes a code snippet against the rules defined in your constitution.md. It uses heuristic analysis (pattern matching, no AI) to detect potential violations: any types, console.log, SELECT *, overly long functions, magic numbers, etc.

It's a quick feedback tool — it doesn't replace a linter, but it verifies that code follows the project-specific architectural conventions defined in your LiveSpec constitution.

How to use — step by step

1
Load a project Click "Load Project" and select a directory containing a .specs/ folder. The constitution rules are loaded from constitution.md and displayed as a read-only preview in the left panel.
2
Paste a code snippet (right panel) Paste the source code to check. The language is auto-detected (JS/TS, Python, Go, SQL).
3
Auto-analysis Analysis runs automatically when the project is loaded and whenever you edit the code (500ms debounce). The score appears immediately in the top bar.
4
Read the score The badge at the top right summarizes: N pass, M warnings, K violations. Violations are blocking issues (MUST NOT / NEVER), warnings are recommendations (SHOULD / AVOID).
5
Explore the results The bottom panel lists each rule with its status:
  • Green (pass) — no problematic pattern detected
  • Yellow (warning) — suspicious pattern, check manually
  • Red (violation) — anti-pattern detected, must fix
  • Gray (N/A) — rule not applicable to the provided code
Click a row to navigate to the relevant code line.
6
Filter results The filter tabs (All / Violations / Warnings / Pass / N/A) let you focus on one category. Useful when there are many rules.
7
Iterate Edit the code directly in the right panel. The analysis re-runs automatically after 500ms. Fix violations and watch the score go up in real-time.

Detected patterns

The analyzer looks for: any usage, console.log, SELECT *, TODO/FIXME/HACK, eslint-disable, @ts-ignore, var instead of const/let, empty catch blocks, magic numbers, direct process.env access, export default, SQL concatenation, functions > 50 lines, files > 300 lines.

Constitution Rule Checker

LiveSpec Playground — Vérificateur heuristique des règles d'architecture

A quoi sert ce playground ?

Le Constitution Rule Checker analyse un snippet de code par rapport aux règles définies dans votre constitution.md. Il détecte par analyse heuristique (pattern matching, pas d'IA) les violations potentielles : types any, console.log, SELECT *, fonctions trop longues, magic numbers, etc.

C'est un outil de feedback rapide — il ne remplace pas un linter, mais il vérifie que le code respecte les conventions architecturales spécifiques de votre projet, telles que définies dans la constitution LiveSpec.

Comment l'utiliser — étape par étape

1
Charger un projet Cliquez sur "Load Project" et sélectionnez un dossier contenant un répertoire .specs/. Les règles de la constitution sont chargées depuis constitution.md et affichées en lecture seule dans le panneau gauche.
2
Coller un snippet de code (panneau droit) Collez le code source à vérifier. Le langage est détecté automatiquement (JS/TS, Python, Go, SQL).
3
Analyse automatique L'analyse se lance automatiquement au chargement du projet et à chaque modification du code (500ms debounce). Le score s'affiche immédiatement dans la barre du haut.
4
Lire le score Le badge en haut à droite résume : N pass, M warnings, K violations. Les violations sont des problèmes bloquants (MUST NOT / NEVER), les warnings sont des recommandations (SHOULD / AVOID).
5
Explorer les résultats Le panneau du bas liste chaque règle avec son statut :
  • Vert (pass) — aucun pattern problématique détecté
  • Jaune (warning) — pattern douteux, à vérifier manuellement
  • Rouge (violation) — anti-pattern détecté, à corriger
  • Gris (N/A) — règle non applicable au code fourni
Cliquez sur une ligne pour naviguer à la ligne de code concernée.
6
Filtrer les résultats Les onglets de filtre (All / Violations / Warnings / Pass / N/A) permettent de se concentrer sur une catégorie. Utile quand il y a beaucoup de règles.
7
Itérer Modifiez le code directement dans le panneau droit. L'analyse se relance automatiquement après 500ms. Corrigez les violations et regardez le score monter en temps réel.

Patterns détectés

L'analyseur cherche entre autres : usage de any, console.log, SELECT *, TODO/FIXME/HACK, eslint-disable, @ts-ignore, var au lieu de const/let, catch vides, magic numbers, accès direct à process.env, export default, concaténation SQL, fonctions > 50 lignes, fichiers > 300 lignes.
