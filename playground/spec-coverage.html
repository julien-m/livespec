Spec Coverage Dashboard

LiveSpec Playground — Spec-to-code traceability dashboard

What is this playground for?

The Spec Coverage Dashboard measures the traceability between your specification and your code. For each Functional Requirement (FR), it checks three coverage levels:

  • In Spec — the FR exists in spec.md (always true by definition)
  • In implementation.md — the FR is mapped in the traceability file
  • In Code (@spec) — a @spec FR-NNN anchor exists in the source code

An FR is "fully traced" only when all 3 levels are green. The dashboard also identifies orphan anchors: @spec references in code that don't match any FR in the spec.

How to use — step by step

1
Load a project (required) Click Load .specs project in the sidebar and select a .specs folder. This loads spec.md (source of truth for all FRs and ACs) and optionally implementation.md (FR → source file → status mapping). You can view both files via the central tabs.
2
Paste the grep output (optional) In the sidebar textarea, paste the result of:
grep -rn "@spec FR-" src/
Each line is parsed to extract the file, line number, and referenced FR.
3
Run the analysis Click Analyze. The dashboard cross-references all 3 sources and generates the FR card grid, the global score, and the gaps report.
4
Read the global score The circular gauge at the top right shows the percentage of "fully traced" FRs (all 3 indicators green). The text provides the exact ratio.
5
Explore FR cards Each card displays 3 colored dots (green = OK, red = missing). The card border reflects overall status: green, yellow, or red. Click a card to expand it and see the full text, ACs, mapped file, and @spec line from the grep output.
6
Review the Gaps Report The bottom panel lists issues in 3 categories:
  • Missing @spec anchors — FRs in the spec but absent from the code
  • Unmapped FRs — FRs in the spec but absent from implementation.md
  • Orphan anchors — @spec in the code that don't match any FR
