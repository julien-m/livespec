Plan Simulator

LiveSpec Playground — Visual dry-run of the implementation pipeline

What is this playground for?

The Plan Simulator lets you visually simulate the execution of a LiveSpec plan before running /spec.implement. It reproduces the full Supervisor cycle: decomposition into steps, Task Payload construction, dispatch to Superpowers, reviewer passes, and checkpoint to progress.md.

It's a verification and learning tool — spot a poorly structured plan, visualize step dependencies, simulate failures, and understand how the pipeline reacts.

How to use — step by step

1
Load a .specs project Click Load Project and select your project directory. The simulator reads the .specs/features/ folder and lists available features.
2
Select a feature Pick a feature from the dropdown. The plan.md is loaded and parsed automatically. The simulator extracts steps, files touched, FR/AC references, and test commands. If a step touches more than 12 files, a Change Scope Guard warning appears.
3
Run the simulation Click Play or press Space. Each step animates through the agent diagram: Supervisor → Build Payload → Superpowers → Implementer → Spec Reviewer → Quality Reviewer → Checkpoint.
4
Control playback
  • Space / K — Play / Pause
  • → / L — Step Forward
  • ← / J — Step Back
  • R — Reset
  • Speed selector: 0.5x, 1x, 2x
5
Simulate a failure Shift+click or right-click on a step card to toggle "Simulate Failure". That step will end as Blocked instead of Done, letting you see how the pipeline handles blockages.
6
Inspect the detail panel Click on a step to see in the right panel: its description, FR/AC addressed, files touched, TDD commands, and current status.
7
Watch the final phase After the last step, the simulator automatically animates Final Validation (Superpowers full suite) then Documenter (finalize). A summary appears: N steps Done, M Blocked.
8
Review progress.md The bottom panel generates the progress.md table in real-time as steps complete, exactly as the Documenter would produce it. You can copy it to pre-populate your feature directory.

Plan Simulator

LiveSpec Playground — Dry-run visual du pipeline d'implémentation

A quoi sert ce playground ?

Le Plan Simulator permet de simuler visuellement l'exécution d'un plan LiveSpec avant de lancer /spec.implement. Il reproduit le cycle complet du Supervisor : décomposition en steps, construction du Task Payload, dispatch vers Superpowers, passage des reviewers, et checkpoint dans progress.md.

C'est un outil de vérification et de compréhension : on peut repérer un plan mal découpé, visualiser les dépendances entre steps, simuler des échecs, et comprendre comment le pipeline réagit.

Comment l'utiliser — étape par étape

1
Charger un projet .specs Cliquez Load Project et sélectionnez le répertoire de votre projet. Le simulateur lit le dossier .specs/features/ et liste les features disponibles.
2
Sélectionner une feature Choisissez une feature dans le menu déroulant. Le plan.md est chargé et parsé automatiquement. Le simulateur extrait les steps, les fichiers touchés, les FR/AC référencés et les commandes de test. Si un step touche plus de 12 fichiers, un warning Change Scope Guard s'affiche.
3
Lancer la simulation Cliquez Play ou appuyez sur Space. Chaque step s'anime dans le diagramme d'agents : Supervisor → Build Payload → Superpowers → Implementer → Spec Reviewer → Quality Reviewer → Checkpoint.
4
Contrôler le déroulement
  • Space / K — Play / Pause
  • → / L — Step Forward
  • ← / J — Step Back
  • R — Reset
  • Sélecteur de vitesse : 0.5x, 1x, 2x
5
Simuler un échec Shift+click ou clic droit sur une carte de step pour activer "Simulate Failure". Ce step terminera en Blocked au lieu de Done, permettant de voir comment le pipeline gère les blocages.
6
Observer le panneau détail Cliquez sur un step pour voir dans le panneau de droite : sa description, les FR/AC adressés, les fichiers touchés, les commandes TDD, et son statut actuel.
7
Suivre la phase finale Après le dernier step, le simulateur anime automatiquement la Final Validation (Superpowers full suite) puis le Documenter (finalize). Un résumé s'affiche : N steps Done, M Blocked.
8
Consulter le progress.md Le panneau du bas génère en temps réel la table progress.md au format Markdown, exactement comme le Documenter la produirait. Vous pouvez la copier pour pré-alimenter votre feature.
