## Unit Testing

**Framework:** pytest 8.x

**What to test:**
- All parsing logic (`validator/parser.py`) — Markdown parsing, frontmatter extraction, section detection
- All schema validation (`validator/schemas/`) — valid and invalid inputs for each spec file type
- All coherence rules (`validator/coherence/rules/`) — each rule in isolation with fixture files
- Auto-fixer logic (`validator/fixer.py`) — each fix action with before/after fixtures
- Pipeline state management (`validator/pipeline.py`) — phase transitions, status updates
- Git operations (`validator/git_ops.py`) — mocked git subprocess calls
- LLM provider abstraction (`validator/llm_provider.py`) — mock provider returning controlled responses

**What NOT to unit test:**
- Full CLI invocations (use integration tests)
- LLM-dependent features (use level_3b tests)
- End-to-end pipelines (use level_3c tests)

**File convention:**
- Test file next to source: `validator/parser.py` → `tests/test_parser.py`
- Test names reference the rule or behavior: `"R1.1: roadmap item without matching feature dir"`

**Example (Python/pytest):**

```python
# tests/test_parser.py
import pytest
from validator.parser import parse_spec_frontmatter

def test_ac001_valid_frontmatter_parsed():
    """AC-001: valid frontmatter is parsed correctly."""
    content = "---\nstatus: Draft\nfeature: auth\n---\n# Spec"
    result = parse_spec_frontmatter(content)
    assert result["status"] == "Draft"
    assert result["feature"] == "auth"

def test_ac002_missing_frontmatter_returns_empty():
    """AC-002: missing frontmatter returns empty dict without error."""
    result = parse_spec_frontmatter("# Spec\nNo frontmatter here")
    assert result == {}
```

## Integration Testing

**Framework:** pytest + subprocess or direct module import with real `.specs/` fixtures

**What to test:**
- Full `livespec validate` invocations with real .specs/ directories
- CLI flag combinations (`--fix`, `--dry-run`, `--staged`, `--coherence-only`, `--format json`)
- Coherence rules against real fixture .specs/ directories (level_3a — no LLM)
- Layer 4 semantic features with SDK-isolated controlled inputs (level_3b)

**Fixture structure:**
- `tests/fixtures/valid/` — well-formed .specs/ directories
- `tests/fixtures/invalid/` — directories with specific violations
- `tests/fixtures/chaos/` — malformed, partial, or corrupted inputs

**Test database:** Not applicable — file-based tool, no database.

---

## E2E Testing (Level 3c)

**Framework:** pytest-asyncio + claude-agent-sdk

**What to test:**
- Full pipeline: `spec-specify` → `spec-plan` → `spec-implement`
- `spec-feature` end-to-end with validation gates
- `spec-check` detecting real gaps in implemented features

**Scope:** These tests are slow (LLM calls, full pipeline). Run on PR only, not on every commit.

---

## Chaos Testing

**Framework:** pytest with `@pytest.mark.chaos`

**What to test:**
- Empty `.specs/` directory
- Malformed YAML frontmatter
- Missing required sections
- Circular references in feature dependencies
- Very large spec files (token budget overflow)
- Binary files in `.specs/`

**Rule:** The validator must NEVER crash (unhandled exception) on any input. It must always return a meaningful error message and a non-zero exit code.

## CI Pipeline

```yaml
# .github/workflows/livespec-tests.yml (existing)
unit-tests:
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@v4
    - uses: actions/setup-python@v5
      with:
        python-version: '3.11'
    - run: pip install -e ".[dev]"
    - run: pytest tests/ --ignore=tests/integration -v --tb=short

integration-3a:
  runs-on: ubuntu-latest
  steps:
    - run: pip install -e ".[dev]" && pip install pyyaml jsonschema anyio
    - run: pytest tests/integration/ -m level_3a -v --tb=short
```

## Iteration Rule

If a test fails after a code fix:
1. Re-read the failing test and the module under test (never trust memory)
2. Check if the fixture needs updating (not just the implementation)
3. If still failing after 2 attempts: stop, read the full module, identify the root cause
