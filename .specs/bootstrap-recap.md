## Project Vision

<!-- Anchor: Q1 — What are you building? -->

**What the project does:**
[INFERRED] LiveSpec is a universal, tool-agnostic specification framework for AI-driven development. It combines a Markdown-based command system (Claude Code slash commands + agents) with a Python CLI validator (`livespec-validator`) that enforces 4 structural layers on `.specs/` directories: Layer 1 schema validation, Layer 2 cross-file coherence rules, Layer 3 SDK-isolated integration checks, and Layer 4 LLM-based semantic validation (scorecard, contradiction detection, plan review).

**The core problem it solves:**
[INFERRED] Specs are throwaway documents — written once, never updated, no traceability between requirements and actual code. LiveSpec makes specs living artifacts: every requirement links to a `@spec` anchor in code, every change is logged in per-feature changelogs, and the validator enforces structural integrity at commit time via a pre-commit hook.

**Success in 2 years looks like:**
[SPECULATIVE] LiveSpec is the default spec framework for Claude Code projects. The Python validator runs in CI on hundreds of open-source and commercial projects. The command/agent system ships features end-to-end with a single `/spec.feature` invocation.

## Platforms

<!-- Anchor: Q3 — Where do they use it? -->

[OBSERVED] Local CLI tool for macOS and Linux. Three delivery surfaces:
1. **Terminal** — `livespec validate`, `livespec pipeline`, `livespec git`, `livespec commit-context`
2. **Git pre-commit hook** — installed via `livespec install-hook`, runs automatically on `git commit`
3. **CI** — GitHub Actions (`pip install -e ".[dev]"` + `pytest` + optionally `livespec validate --staged`)
4. **Claude Code** — Markdown slash commands in `commands/` and agents in `agents/` drive the full spec workflow

No web UI, no mobile, no browser (playground HTML files are static dev tools, not a deployed app).
