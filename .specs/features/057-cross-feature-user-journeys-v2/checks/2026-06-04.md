## Blocking Gaps

### GAP-001 - `implementation.md` is not a LiveSpec implementation map

**Severity:** Blocking for spec-code traceability  
**Evidence:** `rg "Requirement Mapping|Acceptance Criteria Mapping|Last Verified" .specs/features/057-cross-feature-user-journeys-v2/implementation.md` returns no matches.  
**Expected:** A table `Requirement | File(s) | @spec Anchor | Status | Last Verified |` for all FR-001..FR-041, plus `AC | Test File | Status |` for AC-001..AC-046.  
**Impact:** `$spec-check` cannot mark individual FR/AC as fully verified even though tests pass.  
**Suggested fix:** Update `implementation.md` with explicit FR and AC mappings, including changed files and test files.

### GAP-002 - `$spec-test` still scans v1 feature-scoped journey paths

**Severity:** Blocking for workflow consistency  
**Evidence:** `.agent-sync/skills/spec-test/SKILL.md` still says `.specs/journeys/<feature-slug>/*.journey.yaml` are executable user journeys.  
**Expected:** `.specs/journeys/<journey-id>/journey.yaml` global v2 layout, with v1 paths migration-only.  
**Impact:** Agents following `$spec-test` may miss global v2 journeys or revive v1 semantics.  
**Suggested fix:** Replace the data source wording with global v2 journey discovery and v1 migration-only guidance.

### GAP-003 - `$spec-feature` still compiles journeys during test gate

**Severity:** Blocking for compiled-only regression semantics  
**Evidence:** `.agent-sync/skills/spec-feature/SKILL.md` Step 3 says to run `livespec journey compile --feature <NNN-feature-name>` before functional tests.  
**Expected:** Existing regression runs use `livespec journey run --feature <feature-slug>` and must not compile except during explicit create/edit/compile workflows.  
**Impact:** Test gates can mutate compiled artifacts and violate compile-on-create/edit-only behavior.  
**Suggested fix:** Change the gate to impact detection plus compiled-only run; compile only when the command explicitly creates/edits/compiles a journey.

### GAP-004 - `$spec-specify` still proposes v1 feature-scoped journey storage

**Severity:** Blocking for old/new journey creation consistency  
**Evidence:** `.agent-sync/skills/spec-specify/SKILL.md` says interactive journeys go under `.specs/journeys/<feature-slug>/`.  
**Expected:** New journeys are global `.specs/journeys/<journey-id>/journey.yaml`; feature backlinks are generated.  
**Impact:** New feature specs can instruct agents to create stale v1 layout.  
**Suggested fix:** Update `$spec-specify` to propose global journey IDs and delegate creation to `$spec-journey create`.
