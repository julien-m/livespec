# Spec Fix Report - Native Compiler Completeness

## Verdict

**Overall health:** Fixed for the LiveSpec compiler findings surfaced by the Strapt audit.

The audit showed generated Swift and manifest outputs that were incomplete or formatting-blocking. The source defect is LiveSpec feature 057 because the compiler wrote native artifacts even when runner actions were unsupported.

## Gaps Closed

| GAP-005 - Generic XCUITest `testJourney` names | Minor | ✅ Fixed | `validator/journeys/compiler.py` emits `test<JourneyId>Journey()`; compiler test asserts no generic `testJourney()`. |
| GAP-006 - XCUITest assertions used narrow/static text lookup | Major | ✅ Fixed | XCUITest target lookup uses `app.descendants(matching: .any)["<identifier>"]` for stable IDs and text fallbacks. |
| GAP-007 - Supported XCUITest fill/assert_not/open lacked concrete code | Blocking | ✅ Fixed | Compiler emits `typeText`, `XCTAssertFalse`, screenshot attachments, and `openJourneyURL(_:in:)` backed by `XCUIApplication.open(URL)`. 1. Extend runner capability validation from runner-only checks to per-action checks before native artifact writes.
2. Generate concrete XCUITest code for supported actions: open, click, assert, assert_not, fill, screenshot, and back.

4. Add regression tests for unsupported-action rejection, malformed payload rejection, named XCUITest methods, concrete fill/assert_not/open/screenshot output, pre-launch fixtures/mocks injection, no `Process()` URL-open path, and manifest trailing newline.
5. Centralize XCUITest `UI_TEST_JOURNEY_*` environment keys and fail compilation explicitly with `journey_source_unreadable` when a source cannot be reread.
6. Upgrade W14 audit verification documentation to project-level `ruff check .` and `ruff format --check .`, then requalify the type gate honestly: `mypy .` is recorded as a pre-existing project-wide failure, while W13/W15 touched files pass targeted `mypy` and `pyright`.
