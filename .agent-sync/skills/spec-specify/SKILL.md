# spec-specify

Read [review led delivery](../../../system/review-led-delivery.md) before acting. Resolve this link from this skill's real directory when installed through symlinks. This is the default for direct, nested, autonomous and resumed work; no extra flag selects it.

Treat [the former certification workflow](certification.md) as an explicit historical diagnostic only. Do not load or execute it during normal delivery. Historical CLI checks keep their real verdicts and never become automatic delivery prerequisites.

## Work

1. Read the user request, existing project context and applicable conventions; reuse approved decisions.
2. For a new feature choose the next available identifier from the project's actual feature inventory. For a resume or update preserve the existing identity.
3. Write expected behavior, explicit acceptance criteria, scope and unresolved functional choices. Link real relevant designs and contracts without importing an entire unrelated document graph.
4. Ask only for consequential functional ambiguity. Save the specification and update its registry entry; no separate spec review, certificate, goal or pre-implementation Penflow gate.
5. Return the sources and choices for plan preparation. Do not implement application code in this command.

For design work, **Read** `$AIRESOURCES/design/references/design-read-protocol.md` and carry the approved design direction and references into the specification; do not invent a new visual style.
