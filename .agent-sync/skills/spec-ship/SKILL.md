# spec-ship

Read [review led delivery](../../../system/review-led-delivery.md) before acting. Resolve this link from this skill's real directory when installed through symlinks. This is the default for direct, nested, autonomous and resumed work; no extra flag selects it.

Treat [the former certification workflow](certification.md) as an explicit historical diagnostic only. Do not load or execute it during normal delivery. Historical CLI checks keep their real verdicts and never become automatic delivery prerequisites.

## Work

1. Read the roadmap and resolve the requested feature selection, dependency order and existing progress. Honor requested tier, count and resume scope.
2. For each selected feature, apply [spec-feature](../spec-feature/SKILL.md) with the shared policy. Reuse completed work and do not create nested goals or require SHIP_RESULT certification.
3. Script failures travel to that feature's final review. A concrete unresolved material product defect delays that feature; continue independent authorized work where possible.
4. Report actual delivered features, remaining issues and needed decisions. Preserve existing histories and do not reset active mission counters or interpret an old BLOCKED as a new PASS.

Commit, publish, merge and deploy only within existing user authorization. Selecting a batch does not invent that authorization.
